# GCC runtime shipped on the card — AK3918AV100

`./x dist` copies these into `anyka_rust/lib/sys/`, which every binary has in
its `RPATH` (see `tools/ak-linker.sh`). They are the camera's own files, so
loading them from the card instead of `/lib` changes nothing on the firmware
they came from, and keeps the binaries working on a firmware that ships a
different GCC runtime or none.

| File | Needed by | md5 |
|---|---|---|
| `libgcc_s.so.1` | every Rust binary (unwinding) | `4614f44879f61ec2975318ebb74c9529` |
| `libstdc++.so.6` (6.0.21) | `libakv_encode.so` (EV200 `video`/`rtsp` variants) | `7caf8c98b600fa6cb3ede7479da5dd42` |

## Source

`firmware_dump/backup_20260517_192614/explore/mtd5_ROOTFS/rootfs/lib/`, the
root filesystem of the AV100 this project runs on (`system_info/proc_cpuinfo.txt`:
`Hardware : AK3918AV100`). `libstdc++.so.6` is `libstdc++.so.6.0.21` renamed
to its soname — the card is FAT and cannot hold the symlink.

Both are GCC runtime libraries, redistributable under the GCC Runtime Library
Exception.

## Not here

* `libc.so.0`, `ld-uClibc.so.0` — always the firmware's. `PT_INTERP` names
  `/lib/ld-uClibc.so.0`, and uClibc's libc has to come from the same build as
  its loader.
* `libpthread.so.0`, `libm.so.0`, `librt.so.0`, `libdl.so.0` — generated by
  `./x dist` as empty stubs. The crosstool (uClibc 0.9.33) links binaries
  against these split libraries; the camera (uClibc-ng 1.0.31) has all of
  their symbols in `libc.so.0` and ships no such files. An empty object with
  the right soname satisfies the loader, and the symbols bind to `libc.so.0`.
  A copy of `libc.so.0` under those names would load libc twice.

## `firmware-libc.symbols`

The dynamic symbols the firmware's `libc.so.0` and `ld-uClibc.so.0` define,
from the same dump. `./x dist` checks every binary's undefined symbols against
its card-side closure plus this list: the crosstool links against uClibc
0.9.33, so a symbol that links fine can still be missing on the camera
(`pthread_atfork` was).
